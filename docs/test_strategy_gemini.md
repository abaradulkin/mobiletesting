# TEST\_AUTOMATION\_STRATEGY.md

## Стратегия Автоматизации Тестирования: Казуальная Мобильная Игра (C++ Движок)

### 1\. Стек и Инструментарий 🛠️

| Компонент | Инструмент | Роль |
| :--- | :--- | :--- |
| **Движок** | Собственный C++ | Источник игры. **Требуется внедрение Тестового Бэкдора и Accessibility IDs.** |
| **Фреймворк** | Python + Pytest | Основной тестовый фреймворк. Используется для логики, фикстур и управления тестами. |
| **UI Автоматизация** | Appium | Взаимодействие с UI игры через Accessibility ID и управление мобильной ОС. |

| **Шаблон** | Page Object Model (POM) | Для обеспечения **ремонтопригодности** и надежности кода. |

### 2\. Главные Требования к C++ Движку (Критично) 🛑

Для эффективной автоматизации Appium требует способа взаимодействия с элементами, которые не являются стандартными нативными компонентами.

#### 2.1. Accessibility IDs (Локаторы)

  * **Требование:** Каждый ключевой элемент UI (кнопка "Играть", счетчик валюты, настройки, элементы магазина) должен быть **экспортирован** C++ движком как нативный элемент доступности с **уникальным и стабильным `Accessibility ID`**.
  * **Цель:** Исключить использование хрупких координат или XPath.

#### 2.2. Тестовый Бэкдор (Test Backdoor)

  * **Требование:** В движке должен быть специальный API (например, через socket, HTTP-порт или `execute_script` Appium) для управления состоянием игры.
  * **Ключевые функции Бэкдора:**
      * `reset_progress()`: Сброс игры.
      * `set_currency(amount, type)`: Установка валюты.
      * `skip_tutorial()`: Пропуск обучения.
      * `finish_level(result)`: Мгновенное завершение уровня (для тестирования начисления наград).

### 3\. Приоритеты Тестирования и Сценарии 🎯

| Приоритет | Тип Теста | Область Фокуса | Пример Сценария (E2E) |
| :--- | :--- | :--- | :--- |
| **P0 (Smoke)** | **Критический путь** | Запуск, главное меню, основа игрового цикла. | 1. Успешный запуск $\rightarrow$ Вход в Главное Меню. 2. **Бэкдор:** `skip_tutorial()` $\rightarrow$ Играть $\rightarrow$ **Бэкдор:** `finish_level(win)` $\rightarrow$ Проверка экрана результатов. |
| **P1 (Core Loop/API)** | **Экономика и Интеграция** | IAP, прогресс, сохранения, траты. | 1. **Бэкдор:** `set_currency(100)`. Купить предмет (Appium). Проверить, что валюта уменьшилась на 100. 2. **Бэкдор:** `set_level(5)`. Вызвать облачное сохранение (Requests). Сброс игры. Вызвать загрузку. Проверить уровень. |
| **P2 (Регрессия)** | **Навигация и Настройки** | Проверка стабильности старых фич после новых релизов. | 1. Проход по всем вкладкам (Магазин, Настройки, Лидерборд) $\rightarrow$ Назад в меню. 2. Изменение настроек (например, отключение звука) и проверка их сохранения. |

### 4\. Реализация в Pytest (POM) 🐍

#### 4.1. Page Object Model (POM)

  * Создать классы `Page Object` для каждого уникального экрана: `MainMenuPage.py`, `ShopPage.py`, `LevelResultsPage.py`.
  * Каждый класс содержит **только** локаторы (Accessibility IDs) и атомарные методы взаимодействия (`click_play()`, `get_coin_count()`).

#### 4.2. Фикстуры Pytest

  * **`driver_setup` (scope="session"):** Инициализация и закрытие Appium-драйвера.
  * **`game_reset` (scope="function"):** Вызывает метод **Бэкдора** `reset_progress()` перед началом **каждого** теста для обеспечения его независимости.

### 5\. Метрики и Отчетность 📊

1.  **Отчетность:** Использовать **Allure Framework** для наглядного представления результатов, графиков и прикрепления скриншотов при падении теста.
2.  **Ключевые Метрики:**
      * **Pass Rate (P0/P1):** Должен быть ≥ 98%.
      * **Flakiness Rate:** Процент "случайных" падений. Должен быть **\< 1%**; высокий показатель требует немедленного рефакторинга.
      * **Время Регрессии:** Общее время прогона P0/P1. Цель: **менее 30 минут**.
      * **Покрытие Автоматизацией:** Процент ключевых пользовательских историй, покрытых автотестами.

### 6\. Риски и Меры по Смягчению 🛡️

| Риск | Описание | Стратегия Смягчения |
| :--- | :--- | :--- |
| **Хрупкость UI (Flakiness)** | Анимации, задержки, изменение графики в C++ движке. | Использование **явных ожиданий** (Explicit Waits) вместо `sleep()`. Применение **Accessibility ID**. |
| **Сложность локаторов** | Отсутствие стабильных ID от C++ движка. | **Обязательное** внедрение Accessibility ID. Если невозможно — использование Visual Regression Testing как запасной вариант. |
| **Поддержка Бэкдора** | Разработчики могут не обновлять Бэкдор под новые функции. | Включить тестирование самого Бэкдора в Smoke-тесты; тесное сотрудничество команды QA и разработки. |
